# 真实 Herdr 验收（尚未执行）

## 性能口径

目标：1 个现有主管 + 3 个新增 worker，在依赖已安装、CLI 已登录、项目已获用户信任时，
从用户发起建队到主管完成 context 读取并报告 ready 不超过 180 秒。
禁止把依赖安装/登录藏在失败之外，或只报告离线模拟耗时。

至少做 3 次暖启动和 1 次冷启动，保存各次的：

- 用户请求时间、开始脚本时间、返回 ready 时间、主管完成规则读取时间。
- framework.json 的 timings、具体 agent 版本、机器、pane 数量与异常情况。
- 每次总耗时、成功次数和最慢一次；样本足够后再统计 P50/P95。
- 遇到登录/审批/网络问题的运行单列说明，不能悄悄剔除后宣称稳定达标。

`preflight`、`pane_split`、`parallel_native_start` 是不同阶段时长；`attempt_total` 是该次总耗时。
总耗时包括未单列的本地写盘与核验，不能把各项相加再加一次总耗时。

## 功能验收

1. 从真实 main 调用，新建 N 个 worker，原 main、焦点、cwd、tab 不变。
2. 首个实际任务询问各 worker 的角色、主管、PLAN_ID 与文件边界；核对来自原生规则，而非事后补提示。
3. main notify 一项只读任务，worker 写个人日志并独立 notify 结果；禁止启动阶段做此演练来“加速”成绩。
4. worker ask 短问题，main check → reply 一次；重复 reply 被拒，notify 不回 reply。
5. 主管工作中收到结果时能被及时呈现；分别记录 idle/working/blocked 场景，不能宣称有可靠排队。
6. 中断一个启动、制造一次 split 响应丢失，恢复不重复分 pane/启动；错误包含堆栈和原 PLAN_ID。
7. 将一个 pane 中的 agent 换成新会话，旧角色消息被拒；不误投。
8. 各 CLI 的既有用户/项目规则保留；测试已存在的 append layer、中文、空格路径和长规则。
9. 真实上下文压缩/原生会话恢复后核验身份记忆；main 重读 role 文件，记录是否丢失约束。

## 当前证据层次

离线标准库测试能证明调度与错误路径、实际 execve 参数传递、协议字段处理。
它不能证明模型实际遵守角色、Herdr 检测器兼容、真实通信往返或 180 秒时限。
`evals/evals.json` 提供待跑提示和断言；没有伪造 agent A/B 运行或性能数据。
